Sample AI Workflow

A human-reviewed inquiry triage workflow for repetitive, non-critical work.

Illustrative sample. Fictional scenario and synthetic data, created to demonstrate deliverable structure. This is not a paid client engagement, a real audit, or evidence of business results.

Scenario: A fictional agency wants to sort routine project inquiries into a review queue. AI proposes a category and a short summary; a person decides what happens next. This example does not send replies, accept work, or make commitments automatically.

Workflow overview

  1. 1. Receive an inquiry

    A normal form creates a message for the team. The existing inbox remains the source of record.

  2. 2. Validate and minimize inputs

    Check required fields and remove unnecessary personal or confidential information before any model call.

  3. 3. Draft a category and summary

    The model selects an allowed service category or “Needs review” and produces a short summary. Incoming message text is treated as untrusted content, never as system instructions.

  4. 4. Apply deterministic checks

    Validate the output schema, allowed categories, and required fields. Invalid output, timeouts, or uncertain cases go to manual review.

  5. 5. Human review

    A person checks the original message and proposed summary, chooses the service fit, and writes or approves a response.

  6. 6. Log the reviewed outcome

    Record the approved category and review status under the team’s retention policy. No automated production action is taken.

Example input and output

Input“We combine three spreadsheets every month and need one reporting view.”
Suggested categoryDashboard & Reporting Sprint

Validation and acceptance checks

  • Known examples produce permitted categories; ambiguous requests route to manual review.
  • Instruction-like content in an inquiry cannot change workflow rules or trigger external actions.
  • Missing fields, malformed model output, and provider failures preserve the original inquiry and use the manual path.
  • Reviewers compare summaries against source messages for unsupported details before use.

Handoff and ownership

A scoped project would include the workflow design, test examples, failure-path documentation, approved data handling, and a named maintenance owner. The client retains credentials and owns provider usage, ongoing review, maintenance, and operational support. This is non-critical assistance; email and manual review continue if AI is unavailable.
